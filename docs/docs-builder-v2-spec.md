**Status:** draft. Every claim below is either MEASURED (with the number) or marked
UNMEASURED. Nothing is asserted from intuition.
**Last updated:** 2026-08-21
**Evidence:** `/home/hamr/poc/docs-builder/` — POC A, A2, A3, B, C, D, E. Six pre-registered

## 1. What this tool is for

Keep project docs **current, complete and findable**, and split a file when it outgrows
its row in `docs/README.md`.

**It does NOT make docs cheaper to read.** Measured four ways; best case is a tie with
doing nothing. Saying otherwise would be false. See §9.

### The problem it actually solves

barebrowse and bareloop use the same doc structure. barebrowse's biggest doc is 42 KB
and its README works fine. bareloop's is **564 KB** — 13x — and one README row now points
at an 8,297-line monolith. The structure did not fail. One file outgrew it.

## 2. Modes

| Mode | Menu option | Does | Destructive |
|---|---|---|---|
| `/docs-builder reorg` | *First run*, step 1 | classify a WHOLE corpus into product/archive | no (`git mv`, plan reviewed first) |
| `/docs-builder <file.md>` | *First run*, step 3 | big doc -> pages + index | no (original preserved) |
| `/docs-builder reconcile` | *Docs drift* | rebuild index, run lint, propose fixes | no |
| `/docs-builder archive-cleanup [--apply <f>...]` | *Clean archive* | report, or delete named files | **yes** on `--apply` — separate invocation, default keep, requires git |

**A bare `/docs-builder` never guesses.** It runs `due` for context, then asks with
`AskUserQuestion` — three options, no recommendation, no fourth:

- **First run** — sort every `.md` into product/archive, then split anything too big.
- **Docs drift** — rebuild index, re-run lint, report what changed. Nothing moves or splits.
- **Clean archive** — prune `docs/archive/`. Destructive.

Same reasoning as `live-canvas`'s mode pick: the three differ in cost and destructiveness,
so a wrong auto-detected guess is expensive one way and irreversible the other.

**"First run" carries two stops, and they guard different things.** After `discover` prints
its table the user confirms before `apply-reorg` moves anything — that stop guards
*correctness* (a `review`-bucketed file with no H1 is an outright guess). After the moves,
the oversized list is printed with line counts and an estimated cost, and the user picks
which to split — that stop guards *cost* (~$0.39 per 1,000 source lines). Never split N
files in one shot on a list the user has not seen.

## 3. Layout

```
docs/
  README.md          entry point, referenced from CLAUDE.md
  index.md           GENERATED by script. never hand-edited. READER-FACING.
  log.md             append-only:  ## [DATE] operation | description
  product/           specs. reconcile READS, never writes.
  wiki/              synthesised pages. reconcile OWNS these.
  archive/           what got cleaned up: originals, byte-identical, moved via `git mv`.
                     Pruning is a separate, opt-in, destructive invocation.
  .docs-builder/     machine-only working state
    ledger.json        last consolidation SHA + per-doc line counts
    outline.json  labels.json  validate.json  lint.json  tasks/
```

`logs/` is GONE — it and `archive/` were the same idea ("moved out of the way") wearing two
names. One dir, one concept.

**`index.md` stays visible on purpose.** It is what a reader opens first; the winning arm
was *pages + a coarse index*. Burying it in a dot-dir would break the one mechanism that
works. Only machine state goes under `.docs-builder/`.

Protected, never moved: `CLAUDE.md`, `AGENTS.md`, `AGENT.md`, root `README.md`,
`CHANGELOG.md`, `CONTRIBUTING.md`, `LICENSE*`, `SECURITY.md`, `CODE_OF_CONDUCT.md`,
`.github/`, `.claude/`, `node_modules/`, `.git/`.

## 4. The flow

```
1. SCAN      script   headings -> JSON (h1, h2, h3, line ranges, snippet)
2a. PROPOSE  cheap    ONE call over ALL headings -> fixed theme list + glosses
2b. ASSIGN   cheap    chunks of ~20 -> each section gets a theme FROM THAT LIST
3. VALIDATE  script   every key exists, appears once, none invented, none off-list
4. WRITE     mid     one agent per page, reads ONLY its own line ranges
5. ARCHIVE   script   original -> archive/ via verified `git mv`
6. INDEX     script   index.md from steps 1+3
7. LINT      script   supersession (act) / uncited + redundant (propose only)
```

Steps 1, 3, 5, 6, 7 are pure script. Only 2 and 4 use a model.

## 5. Layer 1 — the scan (`docs-builder.cjs scan`)

Vanilla Node, zero deps. One record per H2:

```json
{ "h1": "bareloop — findings",
  "file": "docs/FINDINGS.md",
  "h2": "F17 — the forbidden zone was reachable...",
  "id": "F17",
  "s": 421, "e": 521, "chars": 6306,
  "snip": "**Where:** `src/ralph.js`... **Status:** minted 2026-07-14...",
  "h3": [ {"t": "The four named outcomes", "s": 471, "e": 489} ] }
```

MEASURED on 5 files / 1,055,843 chars: 227 records, 513 H3 rows, 14.0% of source.
Adding a per-H3 snippet costs 18.8% — **not worth it**, H3 headings are already descriptive.

**Every H3 carries its own start/end.** Verified: `sed -n '471,489p'` returns the complete
sub-section — 19 lines instead of the 101-line parent.

Headings inside ``` fences are not headings. H1 is captured (it is the doc's identity;
v1 threw it away and then had a model re-invent it as a "theme").

## 6. Layer 2 — grouping (the only model step)

### 6a. What went wrong in POC A
One call, all 97 sections, output keyed on `{index, findingId}`. Result: one section
dropped, 41 findingIds shifted by one from #55 onward, F105 emitted twice. Nothing
crashed. 70,294 tokens of confident, wrong output.

CORRECTION TO AN EARLIER CLAIM: F105 is a REAL heading (`FINDINGS.md:8150`). It was
duplicated, not invented. The failure is positional misalignment, not fabrication.
(`F65` genuinely has no heading — a real numbering gap the model tried to "fill".)

### 6b. The five rules
1. **Never emit a positional index.** Key on the section's own identity.
2. **One function makes the key; both sides use it.** The key the model is given and the
   key the validator checks must be the same string, produced by the same code.
   MEASURED: bareloop's PRD has **zero** IDs in 86 headings, so the key is heading text.
   CORRECTION: the POC's "86/86 byte-exact" was scored against keys the prompt had
   silently truncated at 110 chars while 55 of the 86 source headings ran longer. It
   passed only because both sides happened to share the truncation. Feeding full headings
   to the same validator produced 55 invented + 55 missing. The build therefore emits an
   explicit `records[].key`, and **guarantees its uniqueness** rather than assuming it —
   bareloop's PRD has 0 collisions at every width tested, but aurora has `## Cache
   Invalidation` in three files.
3. **Chunk to ~20 sections per call.**
4. **Validate against Layer 1 before use** — every key exists, appears once, none
   invented, none off the theme list. Script, not model.
5. **Propose themes globally BEFORE assigning.** See below.

### 6c. Rule 5 is load-bearing — measured
Assign-only, no propose pass: 86/86 keys exact, 0 dupes, 0 invented, 0 missing —
and **68 themes for 86 sections, 57 of them singletons.** Perfect accuracy, useless
grouping. Chunking fixes misalignment; it cannot fix convergence, because convergence
needs global sight.

With a propose pass first (one cheap-tier call over all 86 headings -> 10 themes + glosses),
then chunked assign against that fixed list:

```
sections: 86   labels: 86   invented: 0   off-theme: 0   dupes: 0   missing: 0
VALIDATION: PASS      total lines covered: 5669 of 5669
```
Largest theme 19 sections / 27% of lines. No blob.

## 7. Layer 3 — page writing

One subagent per page. Reads ONLY its own line ranges. Value is CONTEXT ISOLATION.

- Page length is a **ceiling (250 lines), never a target.** MEASURED in POC A: all ten
  pages came in under it unprompted; several agents said padding would be filler.
- Coherence decides grouping, not size. A soft suggestion with +2-5% slack, never enforced.
- **Concurrency cap: 3 concurrent agents, not 10.** CORRECTION: the earlier claim that
  launching 10 killed 9 of 10 mid-run is wrong about the artifacts. All ten pages are on
  disk, complete, with 299 citations at 0 bad / 0 out-of-scope. What was lost was their
  per-call token accounting (subagents do not itemise cost). The cap of 3 is therefore
  **an untuned precaution with no failure behind it** — see §15.
- **Resumes from partial results — IMPLEMENTED, not just stated.** `plan` marks any theme
  whose page already exists in `docs/wiki/` as `done` and drops it from the cost estimate,
  so a re-run relaunches only what is missing. The finished page IS the checkpoint; there
  is no separate state file that can go stale. Verified: 7 of 10 pages present ->
  "pages to write: 3, $0.36".

## 8. Frontmatter (from OKF) — only `type` is required

```yaml
type: finding
title: ...
status: draft | stable | deprecated
sources: [...]
generated: {by: cheap-tier, at: 2026-08-21}
verified: {by: "human:hamr", at: 2026-08-21}
stale_after: 2026-12-01     # ONLY written when asked and answered. never inferred.
```

`verified` is what makes a 27%-precision lint safe to ship: a flag is a **proposal**, and
confirmation is recorded in the file itself. Trust tiers: unverified -> machine-confirmed
-> human-reviewed.

## 9. The index — the most counter-intuitive result

**MEASURED, four arms, two questions, chars counted by replaying command logs:**

| arm | Q1 chars | Q1 finds | Q2 chars | Q2 finds |
|---|---|---|---|---|
| monolith alone (baseline) | 29,561 | 3 | 89,796 | 9 |
| wiki pages, no index | 54,945 | 13 | 112,204 | 34 |
| **wiki + COARSE index** | **29,701** | **29** | **88,623** | **32** |
| H3-grain index + monolith | 81,973 | 28 | 200,209 | ~27 |

### The law
**Cost tracks findings, not structure.** 3 finds -> 29,561. 13 -> 54,945. 28 -> 81,973.
27 -> 200,209. Better navigation does not reduce reading; it raises how thorough the
agent is willing to be. Every address you add is an invitation to read more.

### Why the winning arm wins
NOT because the index helped retrieval. Because **synthesis caps cost** — the pages had
already done the reading, so there was nothing left to re-derive. The index just told the
agent where to stop.

### Consequences
- Reader index is **coarse** and points at **synthesised pages**. 10-100 rows.
  (barebrowse README: 16 rows / 2,579 chars — works. Winning index: 97 rows / 14,946.
  Failed index: **364 rows** / 55,248. The variable is ROW COUNT, not chars-per-row.)
- The H3-grain outline stays **internal** — it is what page writers consume, never the reader.
- **Do not index a monolith as an alternative to splitting.** Worse than both.
- The index carries a completeness guarantee ("if it is not here it does not exist,
  do not sweep") and is **regenerated by script every reconcile** so it cannot drift.
  A stale index that promises completeness is worse than no index.

## 10. Lint — what works and what is cut

MEASURED over two rounds on 5 files / 739 sections / 211 repo files.

| check | precision | decision |
|---|---|---|
| supersession declared in a HEADING | **24/24 (100%) across 4 repos** | **SHIP** |
| uncited (repo-wide sweep) | a fact, not a verdict | PROPOSE ONLY, repo-wide |
| redundancy (shared verbatim sentences) | 1/4 | propose only, never act |
| duplicate ID | 0/6 | CUT — parser bug: `### F15 addendum` is a continuation |
| dangling ID reference | 1/27 | **CUT ENTIRELY** |

### Why dangling is cut
bareloop reuses letter+digit tokens for everything: `N0` = a phase, `S1` = VSM System-1,
`A0` = an experiment arm, `R3` = a mutation, and **`P95`/`P99` are percentiles.** You
cannot infer an ID convention from shape. OKF agrees: *"consumers must tolerate broken
cross-links."*

### Supersession: n=1 became n=4, and the first run FAILED
Re-run on aurora, litectx and justabit — three corpora sharing nothing with bareloop —
precision collapsed to **2/5 (40%)**, not the claimed 100%. Single cause: the term
`invalidat\w*` matches the ordinary heading **"Cache Invalidation"** (3 hits in aurora).
Same failure class as the already-cut dangling-ref lint: a token that means one thing in
bareloop's vocabulary and another everywhere else.

Fix measured before/after on all four repos — drop `invalidat\w*`:

| repo | before | after | precision after |
|---|---|---|---|
| bareloop | 24 | 22 | 22/22 |
| aurora | 4 | 1 | 1/1 |
| litectx | 1 | 1 | 1/1 |
| justabit | 0 | 0 | — |
| **total** | 29 | **24** | **24/24 = 100%** |

Cost: 2 genuine bareloop hits lost (`FINDINGS.md:5055`, `FINDINGS.md:6296`). The trade is
explicit — **-2 true positives to kill 3 false positives, holding 100% precision across
four corpora instead of one.** Consistent with precision-over-recall; the term is cut.

### Why the uncited check is repo-wide AND propose-only
Scoped to the doc corpus it flagged F80 and F106; both are cited elsewhere (a logs file and
`CHANGELOG.md`). A scoped check proposes deleting live docs.

Repo-wide it is correct but still not actionable. bareloop's `O2`, `O3`, `O4` are genuinely
uncited anywhere in 211 files — and must not be removed: they are the middle of a coherent
`O1`–`O5` series whose `O1` *is* cited from `CHANGELOG.md` and `PRD.md`. **Uncited is a
fact; deletable is a judgement.** The check reports the fact and stops. Renamed from
"orphan" so the name cannot imply the action.

### The governing rule, from `/remember`
**Observed beats inferred.** Lint only on what a doc SAYS ABOUT ITSELF. Never on guessed
similarity. Measured: declared 100%, inferred 4-25%. This is the same law friction found
on sessions, rediscovered independently on documents.

## 12. Trigger — BUILT and WIRED

git is the diff engine; the ledger stores only what git cannot — **when we last
consolidated**. Nothing is inferred, so the two cannot drift apart.

`docs-builder.cjs ledger` stamps `docs/.docs-builder/ledger.json` (HEAD SHA + per-doc line
counts). `docs-builder.cjs due` runs `git diff --numstat -M <sha>..HEAD -- docs/` and
classifies every doc:

| kind | means |
|---|---|
| `new` | absent at last consolidation |
| `moved` | same content, new path (`-M` rename detection) |
| `moved+changed` | renamed **and** edited, with the delta |
| `changed` | `+a/-d of N lines (~X%)` — answers *how much* moved, not just *that* it moved |
| `deleted` | in the ledger, gone from the tree |

Due at **>=5 changed docs** — same threshold and same derived-not-counted shape as
`/stash`'s nudge. `due` prints; it never reconciles.

**Wired.** `/remember` step 7 is a detect-only docs check, crash-isolated exactly like the
friction step 0 so it can never block a memory write that already happened. Three-way
skip policy, because a nudge every run in a repo with no docs is noise:

| state | behaviour |
|---|---|
| no `docs/` dir | silent — not applicable |
| `docs/` exists, check could not run | **loud** one-line skip, never silent |
| ran, >=5 changed | one line: `docs: 7 changed since 991f72d3 — run /docs-builder reconcile` |

`/remember` still never reconciles, never writes frontmatter, never edits a page. It reads
`docs/.docs-builder/ledger.json`; `/docs-builder` owns it.

### Why not borrow OKF's ledger
OKF contributes frontmatter (`verified`, `sources`, `status`, `stale_after`) and that is
already adopted. For change detection there is nothing to borrow: git already records
content hashes, renames and line deltas, and a second bookkeeping system would be a second
thing that can be wrong. Dependency hierarchy — the stdlib here is `git`.

## 13. Cost — CLOSED

Method: every page re-written as a measurable `claude -p` on the mid tier call, 3 concurrent, cost read from the reported `total_cost_usd`. No extrapolation.

| step | measured |
|---|---|
| scan / validate / plan / archive / index / lint / ledger / due | **$0** — pure script |
| group (cheap tier, 1 propose + 5 assign) | **$0.23** |
| **write (mid tier, 10 pages, 5,669 lines)** | **$1.9664** |
| **TOTAL** | **$2.20** |
| **per 1,000 source lines** | **$0.39** |

The earlier refusal to extrapolate was right. The shelved guess was ~$1.60 / $0.28 per 1k
lines; the real number is **38% higher**.

### The write cost law — n=10, R² = 0.96

```
cost = $0.083 per page  +  $0.200 per 1,000 source lines
```

Per-page fixed overhead is **42% of the write bill**. `docs-builder.cjs plan` prints this
estimate before any writer launches; on the bareloop PRD it predicted $1.96 against a
measured $1.9664 (0.3% error).

Per-page range: $0.111 (191 lines) to $0.403 (1,528 lines). The **smallest** page cost more
than a previously measured 775-line page — that is the fixed term showing up.

### The flat-cost finding does NOT generalise
Every cheap-tier group call landed at 35–41K tokens regardless of input size. The mid-tier write
calls are ~58% input-driven. Cost shape is a property of a *step*, not of the pipeline.
Chunk 40–50 remains untested, but now buys <5% of the total bill.

Pricing used: Haiku 4.5 $1/$5 per MTok; Sonnet 5 $2/$10 (intro, through 2026-08-31).
Looked up live, not recalled. `total_cost_usd` is API-equivalent cost, not plan billing.

### Harness bug caught before the numbers were believed
`--allowed-tools ""` does **not** disable tools. One writer used `Write` and emitted a
652-char summary instead of a page; its first cost ($0.4569) was tool-turn inflated. Re-run
with explicit `--disallowed-tools` gave $0.4035, and that is the figure used. bareloop
`git status` was verified clean before and after — the stray file landed in the POC dir.

## 17. Build validation

`packages/claude/skills/docs-builder/` — `docs-builder.cjs` (385 lines, vanilla Node, zero
deps, six subcommands) + `SKILL.md` (204 lines, down from 309). `references/templates.md`
deleted per §14.

Every subcommand was run against the POC's own numbers. Nothing is claimed that was not
observed:

| test | bar | result |
|---|---|---|
| `scan` bareloop PRD | 86 sections, 5,669 lines, 0 IDs | **86 / 5,669 / 0** ✓ |
| `validate` on the POC's real labels | PASS, 0/0/0/0, 5669 of 5669 | **PASS** ✓ |
| `validate` negative control | catch 1 each of missing/dupe/invented/off-theme | **1/1/1/1, exit 1** ✓ |
| `plan` | 10 pages, 5,669 lines | **10 / 5,669**, est. $1.96 vs actual $1.9664 ✓ |
| `index` | ≤100 rows, coarse, page-grain | **86 rows / 10 pages / 10,420 chars** ✓ |
| `archive` | verified move, refuses overwrite | **sha256 MATCH via `git mv`, old path empty, exit 1 on overwrite** ✓ |
| `ledger` + `due` | classify new/moved/moved+changed/changed/deleted | **all 5 correct, no double-count** ✓ |
| failure-path probes | clean errors, no silent pass, no data loss | **4 bugs found and fixed, see below** ✓ |
| full repo test suite | green after all changes | **138/138** ✓ |
| `plan` resume | skip already-written pages | **7 done -> 3 TODO, $1.96 -> $0.36** ✓ |
| `lint` bareloop | 22 supersession after the fix | **22** ✓ |
| `lint` 4 repos | 100% supersession precision | **24/24** ✓ |
| citation groundedness (10 pages) | 0 bad, 0 out-of-scope | **294 cites, 0 / 0** ✓ |

Two bugs the build caught that the POC did not:

- **The key contract.** Full headings against the POC's truncated labels produced 55
  invented + 55 missing. Fixed by one shared key function with guaranteed uniqueness (§6b).
- **Path resolution.** Source `.md` paths are repo-relative; JSON artifacts the pipeline
  produces are cwd-relative. Conflating them made `plan` look for `outline.json` inside the
  repo being documented.
- **git's rename form does not end in `.md`.** A move is emitted as
  `docs/{old.md => new.md}`, so an `endsWith('.md')` filter applied to the raw path
  silently dropped **every** move from `due`. Parse the rename first, filter second. Same
  species as the other two: a check that agrees with reality for the wrong reason.


### Bugs found by probing failure paths (round 2)

Four found by deliberately driving the script into states the happy path never reaches.
All four fixed and re-tested; the full pipeline re-ran to the same numbers afterward.

| # | bug | what it did | fix |
|---|---|---|---|
| B1 | git failure unguarded | dumped a raw Node stack trace at the user when run outside a git repo | one guarded `git()` helper, clean one-line message |
| B2 | ledger SHA unreachable | crashed after a rebase / amend / GC | `cat-file -e` pre-check → "re-stamp with `ledger`" |
| B3 | `labels.json` with no `themes[]` | the off-list check **silently passed anything** — a gate that quietly stops checking | hard `die`, the gate can no longer disable itself |
| B4 | theme slug collision | **DATA LOSS.** `"A/B testing"` and `"A-B testing"` both slug to `a-b-testing`; `plan` reported 2 pages and wrote 1 task file, so a whole page's content silently vanished | slugs assigned once for all themes together, disambiguated with a loud WARN |

Also hardened, not an observed failure: `execFileSync` defaults to a 1 MB buffer, which
`git ls-files` can exceed on a large repo. Raised to 64 MB.

**B3 and B4 are the same species as the three earlier bugs** — a check that agrees with
reality for the wrong reason, or a name that two different things share. That is now five
of a kind, and it is the class worth probing first on any future step.

One improvement over the POC scanner: headings inside ``` fences are excluded, which drops
982 false sections on aurora (2,213 → 1,231).

The write-cost law predicted **$2.05** for 11 pages / 5,669 lines against an actual

### Three bugs only a real run could find

**1. Keys the model cannot echo (the gate caught it, cost $0.28).**
The first assign pass FAILED validation: 11 of 86 keys came back wrong. Neither was a model
failure — both were mine.
- **5 keys**: truncating at 110 chars lands on a space (9 of 86 headings), and no model
  faithfully echoes a trailing space. Fixed: keys are trimmed.
- **6 keys**: the prompt wrote `KEY: <text>` then the snippet on the next line, so a key cut
  mid-sentence had no visible end and the model glued snippet text onto it. Fixed: keys are
  delimited `<<<KEY>>>...<<<END>>>`.

**The rule: never ask a model to reproduce a boundary it cannot see.** The gate did exactly
its job — it refused bad grouping before $2 of page writing was spent on it.

**2. `.js` is unloadable in a `"type": "module"` project — a hard blocker.**
Installed project-locally into a repo whose `package.json` declares `"type": "module"`, a
`.js` file loads as an ES module and every `require` throws before the first line of work.
bareloop is such a project. Renamed to **`docs-builder.cjs`**.

> **`packages/*/commands/remember/friction.cjs` has the identical bug**, pre-existing and
> shipping in all four packages today. `/remember`'s step 0 dies in any ESM project. Not
> fixed here — it is a four-package sweep and a separate change.

**3. A checkpoint nobody validates is not a checkpoint — the worst bug found.**
The page writers hit a genuine account session limit (HTTP 429) on the last batch. Two
writers failed, and the error string was written into `docs/wiki/` as the page body. `plan`
then reported **"all pages written — nothing to do"** while two themes covering **2,238
source lines** had no page at all. A silent, successful-looking, incomplete cleanup.

Fixed: `plan` validates each checkpoint (YAML frontmatter present, >= 10 lines) and reports
`PARTIAL` instead of `done`, so a failed page is rewritten. Re-verified: 9 done / 2 PARTIAL,
$0.61 to finish. **Existence is not completion.**

### On the concurrency cap
The session limit is real and was reproduced at a cap of **3**, so the cap is not what
prevents it. What matters is that failure is *survivable*: nothing is written from a failed
call, and `plan` can tell a finished page from wreckage. Resume, not concurrency, is the
protection. The right cap is still unmeasured.

## 19. Mode 0 — reorg (whole-corpus classification)

v1's own scope was never "split one file" — it was "reorganize `/docs`," done by handing an
agent a prose rulebook (KEEP/CONSOLIDATE/ARCHIVE, "when uncertain -> ARCHIVE") and letting
it read, judge and `mv` everything itself. Same shape as the model-does-bookkeeping failure
this whole rebuild replaced elsewhere (27% correct). `reorg` rebuilds v1's SCOPE with v2's
DISCIPLINE: classification is mechanical script, archive/product moves are verified `git
mv`, nothing executes until a plan is written and can be reviewed.

Descoped on purpose: v1's CONSOLIDATE (merging two docs into one). That rewrites content —
a different, higher-risk operation than anything measured in this file. Not silently
dropped, explicitly out of scope.

### 19a. Classification rules, and the false positives that shaped them

Four buckets: `product` (default, has an H1, under the size ceiling, no archive signal),
`oversized` (over `OVERSIZED_LINES`, default 500, **an UNMEASURED starting point** — feed
through the Mode 1 split pipeline), `archive` (path/filename/content signal), `review` (no
H1 — genuinely can't tell).

**The archive-content signal went through the same failure class twice, on real data, in
the same session.**

Round 1 (case-insensitive `closed|frozen|archival|archived|superseded|...` over the
opening 20 lines) false-positived on bareloop's real `docs/` — not a crafted fixture:

| file | matched | actual meaning |
|---|---|---|
| `docs/FINDINGS.md` (root, 8,298 lines, an ACTIVE log) | "closed" | *"adaptlearn's F1-F23 are a closed record"* — describes a DIFFERENT file |
| `p-palette-design.md` (a current, locked, in-build spec) | "superseded" | *"Supersedes **nothing**"* — negated |
| `n4-verdict-classes-build.md` (an active build plan) | "frozen" | *"BUILDS three frozen records"* — an input, not itself |
| `upstream-ledger-design.md` (a current design) | "archived" | *"against its archived spines"* — data it references |

Round 2 fix: require the SAME words in **ALL CAPS**, case-sensitive. This corpus's own
writing convention — independently observed, not designed around — SHOUTS a genuine
self-declaration (`**Status: CLOSED**`, `(FROZEN 2026-07-25, before any number; archival)`)
while narrative mentions of the identical word stay lowercase or Title Case. Re-tested
against the full corpus:

| file | before | after |
|---|---|---|
| `FINDINGS.md`, `p-palette-design.md`, `upstream-ledger-design.md`, `n4-verdict-classes-build.md` | false archive | **product/oversized (correct)** |
| `REPORT-AIM.md`, `JOB2-PREREG.md`, `AURORA-PREREG.md`, 8 more PREREG/design docs | archive | **archive (still correct)** |

Traded away, and named rather than hidden: **2 real misses** —
`MATERIALS-PREREG.md` ("Frozen 2026-07-26") and `TESTGEN-PREREG.md` ("(frozen)") are
genuinely archival but not shouted, so land in `product`/`oversized` instead. Consistent
with this file's precision-over-recall law throughout, and safe by construction: a miss
here is one bucket short of ideal, not a wrongly-archived doc, and nothing moves before a
human sees the plan.

**A v1 heuristic was tested and dropped, not carried forward on faith:** "dated filename ->
likely stale." `2026-07-28-p-palette-design.md` is a current, actively-built spec named
with a date, same as every other design doc in this corpus's convention. A dated filename
alone proved nothing about staleness on real data.

**Filename-keyword signal** (`REPORT_`, `STATUS_`, `PHASE_`, `DRAFT`, `WIP`, `OLD`, `TEMP`,
…, from v1, kept) — checked against ~35 files across bareloop's `docs/`: 1 match
(`REPORT-AIM.md`), true positive, already independently confirmed by the content signal.
No false positives found, but n is small; kept as a weak secondary signal, never sole cause.

### 19b. A real bug the discipline itself would have missed if not tested for

`doArchive`'s original form called `die()` (exit the process) on any failure — refusing to
overwrite, missing file, hash mismatch. `apply-reorg` wraps many moves in one run; wrapping
a `die()`-calling function in `try/catch` does nothing, because `process.exit` doesn't
throw. **The first bad file in a batch would have silently killed the entire reorg run
with no indication which files it never reached.** Caught before it shipped, by testing the
negative: a forced destination collision. Fixed by splitting `archive()` into a throwing
core (`doArchive`) used by `apply-reorg`, and a CLI wrapper that turns the throw into
`die()` for single-invocation use. Re-verified: one forced collision skips, logs, and the
run continues — `{"moved":1,"skipped":1}`.

### 19c. End-to-end on the real bareloop corpus (35 files, not a fixture)

| bucket | count |
|---|---|
| product | 16 |
| archive | 12 |
| oversized | 8 (includes the just-split PRD.md's sibling docs — `FINDINGS.md` 8,298 lines, `UPSTREAM-ASKS.md` 2,066, `LAYERS.md` 959, `CYBERNETICS.md` 546, and 4 more) |
| review | 0 |

`apply-reorg`: 28 moved, 0 skipped, 8 correctly left in place with a follow-up list. Non-.md
experiment artifacts (`.json`, `.jsonl`, `.py`) in the same directories were correctly never
touched — `discover` only walks `*.md`. `git status` showed clean Renames (`R`), confirming
history survives the move once committed.

### 19d. Open, honestly

- The 500-line oversized ceiling is unmeasured, a stated default.
- Validated on one corpus family (bareloop). The SHOUTED-caps rule leans on that corpus's
  own convention; a differently-styled repo should just get fewer `archive` hits (recall
  loss, not a false-archive risk), but that is inferred from the design, not independently
  confirmed on a second, differently-styled real corpus.
- Not yet run on a repo this session doesn't already have full visibility into.

## 20. Mode 2 — reconcile (real subcommand, not model-followed prose)

§2's table always listed `reconcile` as a mode, but for a while it existed only as prose
telling the model to run scan, validate, index and lint in order by hand — the exact
model-does-bookkeeping shape this rebuild exists to remove elsewhere (27% correct, §6).
Built as a real subcommand instead:

```bash
REPO=<repo> node docs-builder/docs-builder.cjs reconcile
```

It runs **scan -> validate -> index -> lint** over every tracked `docs/**.md`, excluding
`docs/archive/`. Never touches `product/`; owns `wiki/`. validate and index both need a
theme assignment, and only the model's grouping step (§6) can produce one — `reconcile`
never calls a model itself, so with no `labels.json` present it **LOUD-SKIPs** those two
steps and says exactly why, rather than inventing labels or passing silently. scan and lint
always run regardless, since neither needs a theme.

## 21. Mode 3 — archive-cleanup (the only destructive command)

§2's table originally specified this mode as "moves to `docs/archive/`, never deletes" —
**that was wrong, and self-contradictory on inspection**: `archive-cleanup` is the command
that cleans OUT `docs/archive/` itself, so "never deletes" described a prune command that
could never prune anything. There is no version of this mode that both cleans the archive
and never deletes from it. The spec was wrong; what replaced it is a delete gated on
explicit human confirmation, not a non-destructive move:

```bash
REPO=<repo> node docs-builder/docs-builder.cjs archive-cleanup                  # report only
REPO=<repo> node docs-builder/docs-builder.cjs archive-cleanup --apply <f>...   # delete named files
```

Bare invocation only **reports** candidates: every `.md` under `docs/archive/`, tracked or
not, cross-referenced against every tracked file that could cite it, flagged uncited or
not. Nothing is removed. Uncited is a fact, not a verdict — bareloop's own `O2`-`O4` are
genuinely uncited and must stay, the middle of a coherent series, so this command will
never bulk-prune and has no `--all`. `--apply` deletes exactly the files named on the
command line, and only after a human has confirmed which ones — the model MUST obtain that
confirmation before calling `--apply`; this is a requirement on the caller, not a courtesy.

It refuses to run on a dirty git tree, so the delete never gets entangled with other
uncommitted work. Tracked files go via `git rm` — gone from the tree, recoverable from history
until the next commit. Untracked files have no history to fall back to, so they're unlinked
directly; the output flags each one **NOT recoverable**, rather than treating the two cases
as one operation. Appends one line to `docs/log.md`, same as every other mutating command.
